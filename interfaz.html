El aspecto, los materiales y las herramientas

Raven no solo coloca widgets: define un sistema visual completo con temas, estilos y cristal, y trae las piezas que necesitan los editores y las herramientas de autor. Aquí tienes cómo se combinan y qué funciones las controlan.

Temas y estilos

Un tema es lo que da aspecto a cada widget: unos cuarenta colores por rol (no por widget: accent, panel, text…), una veintena de métricas (tamaño de fuente, radio de esquina, altura de control…), un material, una fuente, los colores del código y una lista de estilos para un tipo de widget, una clase, o ambos.

Raven incluye cuatro temas: Dark, Light, GlassDark y GlassLight. El ejemplo examples/themes los recorre todos y permite editar sus archivos mientras se ejecuta.

Cambiar un tema desde C

Se puede partir de uno de los cuatro temas y retocar cualquier color o métrica. Rtheme_set_accent deriva de un solo color los tonos hover, pressed, el foco, la selección y los enlaces.

Rtheme_apply(R_THEME_DARK);                                /* uno de los cuatro                        */
Rtheme_set_accent(0.13f, 0.83f, 0.93f);                    /* el acento y todos sus tonos              */
Rtheme_set_color(R_COLOR_PANEL, 0.07f, 0.10f, 0.17f, 1);   /* un color concreto                        */
Rtheme_set_metric(R_METRIC_CORNER_RADIUS, 10);             /* una métrica concreta                     */
Rtheme_set_material(R_MATERIAL_FROSTED_GLASS);             /* de qué están hechas las superficies      */
Rtheme_set_dark(R_TRUE);                                   /* tema oscuro: tinte del cristal y código  */

Para un widget y todo lo que contiene: Rwidget_set_color, Rwidget_set_metric y Rwidget_set_material. En XML equivalen a Color.Accent="#F00", Metric.CornerRadius="4" y Material="Glass".

Estilos y clases

Un estilo da valores a los widgets de un tipo, de una clase o de ambos. Un widget puede tener varias clases separadas por espacios: Class="card danger".

Rtheme_set_style_metric("Button", NULL, R_METRIC_CORNER_RADIUS, 16);            /* todos los botones          */
Rtheme_set_style_color(NULL, "danger", R_COLOR_ACCENT, 0.98f, 0.44f, 0.52f, 1);  /* la clase "danger"          */
Rtheme_set_style_color("Label", "eyebrow", R_COLOR_TEXT, 0.13f, 0.83f, 0.93f, 1);
Rtheme_set_style_material(NULL, "card", R_MATERIAL_TINTED_GLASS);

Rwidget_add_class(campo, "invalid");    /* el cambio de clase se ve al instante */
Rwidget_remove_class(campo, "invalid");

Cuando varios estilos dan el mismo valor, gana el que tiene tipo y clase sobre el de solo clase, y este sobre el de solo tipo. Entre iguales, gana el último definido. Lo que se pone directamente en el widget (Rwidget_set_color, Color.*) gana sobre cualquier estilo.

◆

Los colores y métricas puestos con Rwidget_set_color se heredan por lo que contiene el widget. Un estilo se aplica solo a los widgets que nombra, no a sus hijos; la excepción es el color del texto, que cada widget toma del ancestro más cercano que lo tenga.

Archivos de tema

Un tema también se escribe en XML. Se carga sin aplicarlo y luego se usa por su nombre. Los errores se informan con su línea y el resto del archivo se sigue usando.

<Theme Name="Ocean" Base="Dark" Accent="#22D3EE" CornerRadius="10">
    <Colors Window="#0B1220" Panel="#111A2C" Text="#DCE7F5" Separator="#FFFFFF1A"/>
    <Metrics ControlHeight="32" Spacing="8"/>
    <Glass Frost="0.8" Refraction="1.2" Saturation="1.1" Rim="1" Shadow="1"/>
    <Syntax Keyword="#7DD3FC" String="#86EFAC" Comment="#64748B" Heading="#22D3EE"/>

    <Style Widget="Button" CornerRadius="16"/>
    <Style Class="danger" Accent="#FB7185" AccentHovered="#FDA4AF" AccentPressed="#E11D48"/>
    <Style Class="card" Panel="#1B2742" CornerRadius="18" Material="Solid"/>
    <Style Widget="Label" Class="eyebrow" Text="#22D3EE" FontSize="12"/>
</Theme>
const char* name = Rtheme_load("themes/ocean.xml");   /* "Ocean": se guarda, no se aplica */
Rtheme_use("Ocean");                                   /* pasa a ser el tema de la aplicación */
Rtheme_save("mi-tema.xml", "Mine");                    /* guarda el tema en uso con los cambios */

Rtheme_get_count y Rtheme_get_name_at listan todos los temas, incluidos los cuatro incorporados.

Un tema para una parte de la ventana

Theme en un widget hace que ese widget y todo lo que contiene usen otro tema, aunque cambie el de la aplicación. Los menús y popups que se abren desde ahí también lo llevan.

<Border Theme="Paper" Padding="18"> ... </Border>        <!-- un tema por nombre          -->
<Border Theme="themes/paper.xml"> ... </Border>          <!-- o directamente desde archivo -->
<Window Theme="Ocean" ...>

Desde C se hace con Rwidget_set_theme(widget, "Paper"). La isla de una ventana usa esta capacidad: siempre es oscura salvo que se le diga Theme="Default".

Recarga en vivo

Los archivos de tema, como los de interfaz, se vigilan mientras la aplicación corre: guarda el archivo y cada widget que usa ese tema sigue el cambio. Rxml_set_live_reload(R_FALSE) (o RAVEN_LIVE_RELOAD=0) lo desactiva para una aplicación distribuida; Rxml_set_reload_callback avisa cuando un archivo se cargó de nuevo, y Rxml_check_files() comprueba en ese momento en lugar de esperar al siguiente tick (cinco veces por segundo). Un archivo con errores no cambia nada.

Glass y blur

Un material es de lo que está hecha la superficie de un widget. Los temas de cristal son solo un punto de partida: cualquier widget puede pedir su propio material.

MaterialQué se ve
SolidRelleno con los colores del tema.
GlassCristal claro: lo que hay detrás se ve, doblado en el borde.
FrostedGlassDesenfocado: los colores de detrás, sin sus formas.
TintedGlassDesenfocado y teñido por el tema: el más fácil de leer.
 
Rtheme_apply(R_THEME_GLASS_DARK);                 /* un tema viene con su material              */
Rtheme_set_material(R_MATERIAL_FROSTED_GLASS);    /* todos los que no tengan uno propio          */
Rwidget_set_material(panel, R_MATERIAL_GLASS);    /* este widget y lo que contiene               */

En XML: Material="TintedGlass" en cualquier widget. Sea cual sea el material, un popup es más opaco que el panel del que sale, y un panel más que la barra que tiene encima, para que lo de arriba se lea siempre.

Con cristal, los controles son cápsulas que muestran una versión desenfocada y más viva de lo que hay detrás; su borde lo dobla como una lente y recoge una luz colocada arriba a la izquierda. El pomo de un slider se convierte en una lente clara mientras se arrastra.

⚠

El cristal necesita algo detrás. Los temas de cristal ponen cada ventana sobre un gris oscuro liso (oscuro) o blanco liso (claro). Rwindow_set_background pone una imagen detrás, y un tema puede dar manchas de color con Wallpaper="#101020, #3040C0, #C02080". Un widget personalizado dibuja cristal con Rdraw_glass.

Cómo se renderiza

Un frame que contiene cristal se dibuja en una imagen fuera de pantalla; donde empieza el cristal, lo ya dibujado se copia y se desenfoca, y las primitivas de cristal muestrean tanto la copia nítida como la desenfocada. El cristal sobre cristal funciona. Un frame sin cristal se dibuja directamente en la ventana: los temas sólidos no cuestan nada extra.

Blur y ventanas que se ven a través

BackgroundBlur es un panel que muestra lo que hay detrás desenfocado, sin el doblado ni el borde del cristal. Tiene cuatro estilos:

EstiloQué hace
PlainSolo desenfocado.
FrostedDesenfocado, un poco velado y con grano fino (por defecto).
GlassDesenfocado y doblado en el borde, como el material de cristal.
NativeAbre la ventana: el sistema desenfoca el escritorio que hay detrás.
 
<Window Transparent="true" Backdrop="Blur" Borderless="true">
    <BackgroundBlur Style="Native" CornerRadius="24" Padding="22" Tint="#10141C99">
        <VBox Spacing="12">
            <Label Text="Panel flotante"/>
            <Button Text="Cerrar" OnClicked="window.close"/>
        </VBox>
    </BackgroundBlur>
</Window>

Una ventana creada con Transparent="true" (R_WINDOW_TRANSPARENT) no se rellena: donde no dibuja ningún widget se ve lo que hay detrás en la pantalla. Backdrop (Rwindow_set_backdrop) pide al sistema lo que pone ahí: nada, un blur, o los materiales acrylic y mica de Windows 11. Rwindow_set_opacity atenúa la ventana entera.

Todo depende del sistema de ventanas: Windows 10 y 11; X11 con compositor y KWin para el blur. Rwindow_get_backdrop dice qué se consiguió, y donde no hay nada disponible la misma interfaz se ve sobre un fondo liso.

Editor de texto

R_WIDGET_TEXT_EDITOR (<TextEditor>) edita texto de cualquier número de líneas: selección, portapapeles, deshacer, números de línea y ajuste de línea. Con un lenguaje colorea el texto, propone palabras mientras se escribe (las del lenguaje y las que ya están en el texto; Ctrl+Space las pide), muestra qué corchete cierra a cuál, cierra corchetes y comillas, indenta y comenta líneas (Ctrl+/).

Rtext_editor_set_language(editor, Rlanguage_for_file(ruta));   /* "main.rs" -> "Rust" */

Rtext_editor_set_completion_callback(editor, mis_propuestas, user);
Rtext_editor_add_marker(editor, inicio, fin, "error: falta un ;", R_MARKER_ERROR);

Los lenguajes incorporados son C, C++, C#, Java, JavaScript, TypeScript, Python, Rust, GLSL, JSON, CSS, XML y HTML (con el JavaScript y el CSS que contiene). Cualquiera se puede cambiar y se pueden declarar otros con Rlanguage_register: un lenguaje es una descripción (sus palabras, sus comentarios, sus comillas), no código.

💡

El editor sabe lo que puede deducir del texto: no es un language server. Lo que necesita entender un programa entero viene de fuera por dos puertas: Rtext_editor_set_completion_callback (tus propuestas, listadas primero) y Rtext_editor_add_marker (subrayar un fragmento con un mensaje: los errores de un compilador). Un cliente LSP se conectaría ahí; Raven no incluye uno.

Markdown

Una etiqueta con Markdown="true" dibuja el texto formateado: títulos, listas, citas, bloques de código, tablas y enlaces que abren o disparan acciones. En el editor, el texto sigue tal como se escribió y se estiliza donde está.

<Label Markdown="true" Wrap="true">
    ## Notas
    Texto **fuerte** y *enfatizado*, `código`, un [enlace](https://example.org),

    - una lista
    - [x] con una casilla
</Label>

<TextEditor Markdown="true"/>

Rlabel_set_markdown, Rlabel_set_link_callback y Rlabel_get_plain_text completan el lado de C. En el editor, el resaltado de Markdown viene de fábrica.

Personalizar la apariencia del código

Los colores de sintaxis salen del bloque <Syntax> del tema (Comment, String, Number, Keyword, Type, Function, Tag, Attribute, Punctuation, Directive, Heading, Strong, Emphasis y Link). Cambiar el tema cambia el editor entero sin tocar el documento.

Rtheme_set_color(R_COLOR_CODE, 0.05f, 0.07f, 0.11f, 1.0f);   /* fondo del código */
Rtheme_apply(R_THEME_GLASS_DARK);                            /* también cambia la sintaxis */

Docking

Un DockArea ordena sus hijos como paneles con pestañas. El usuario arrastra una pestaña a otra barra de pestañas, a un lado de un panel o a un borde del área; los paneles vuelan a su nueva posición.

  • Slot.Dock, Slot.DockTo y Slot.DockSize dan la disposición inicial en XML.
  • Rdock_area_add_panel añade paneles desde C.
  • Rdock_area_save_layout y Rdock_area_load_layout convierten la disposición en un texto corto y la restauran.
<DockArea Name="docks" Slot.Fill="1">
    <Border Slot.Dock="Left" Slot.DockSize="260">
        <FileBrowser/>
    </Border>
    <TabView Slot.Dock="Center">
        <Tab Title="Editor"><TextEditor Name="editor"/></Tab>
        <Tab Title="Consola"><Label>Listo.</Label></Tab>
    </TabView>
</DockArea>
Rid docks = Rwidget_find(window, "docks");
Rid panel = Rdock_area_add_panel(docks, editor, "Editor");
Rdock_area_set_panel_closable(docks, panel, R_TRUE);

const char* layout = Rdock_area_save_layout(docks);   /* texto corto, válido hasta la próxima llamada */
Rdock_area_load_layout(docks, layout);

Desprender pestañas

Una pestaña arrastrada fuera del área se lleva su panel a una ventana propia; arrastrada de vuelta sobre un dock, vuelve a acoplarse. Un doble clic en la pestaña, o cerrar la ventana, devuelve el panel a donde estaba. Rdock_area_set_tearable (o Tearable="false") mantiene los paneles dentro de su ventana.

La isla

Una píldora en la parte superior de la ventana que se despliega bajo el puntero, con un clic, o desde C. Sus dos contenidos se funden mientras cambia de tamaño; un clic la fija abierta y un clic fuera la cierra. Es oscura sea cual sea el tema, como la muesca de un teléfono (Theme="Default" le da el tema de la ventana). Es opcional, y una Island también se puede usar como widget normal en cualquier sitio.

<Window ...>
    <Island>
        <Label Text="3 mensajes"/>                      <!-- plegada  -->
        <VBox> ... cualquier cosa ... </VBox>           <!-- desplegada -->
    </Island>
    <VBox> ... el contenido de la ventana ... </VBox>
</Window>
Risland_set_expanded(isla, R_TRUE);       /* queda abierta  */
Risland_expand_for(isla, 2.0);            /* se abre 2 s para decir algo y se pliega */

Herramientas de autor

El header raven_tools.h agrupa los widgets de las herramientas creativas. Cada uno mantiene un modelo pequeño que la aplicación rellena y lee, o que escribe en XML.

Selector de color

Cuadrado de saturación y valor, franja de tonos, opacidad, código, números y muestras. Rcolor_picker_set_popup lo convierte en una muestra que abre el selector en un popup.

Rid picker = Rcolor_picker_create();
Rcolor_picker_set_changed_callback(picker, on_color, NULL);
Rcolor_picker_set_popup(picker, R_TRUE);
Rcolor_picker_set_color(picker, 0.13f, 0.83f, 0.93f, 1.0f);

Línea de tiempo

Ajusta a frames, al playhead y a los otros elementos; mueve varios a la vez, estira clips por sus extremos, selecciona con un rectángulo, hace zoom con Ctrl + rueda y reproduce.

Rid timeline = Rtimeline_create();
int track = Rtimeline_add_track(timeline, "Camera");
int clip  = Rtimeline_add_clip(timeline, track, 0.0, 3.5, "Plano general");
Rtimeline_add_key(timeline, track, 6.0);
Rtimeline_set_time_callback(timeline, on_time, NULL);       /* al arrastrar o reproducir */
Rtimeline_set_changed_callback(timeline, on_item, NULL);    /* al mover o estirar        */

Grafo de nodos

Se desplaza con el botón central o Alt + arrastrar, y hace zoom alrededor del puntero. Los pines tienen tipo y color por tipo, y solo se conectan a los que encajan. Un cable se estira desde un pin, se siente atraído por los pines compatibles y se puede soltar sobre un nodo; tomado por su extremo, se conecta en otro sitio o se suelta. Los cables cuelgan y se balancean cuando sus nodos se mueven.

Rid graph = Rnode_graph_create();
int noise = Rnode_graph_add_node(graph, "Noise", 40, 60);
int out   = Rnode_graph_add_output(graph, noise, "Value", "number");
int blend = Rnode_graph_add_node(graph, "Blend", 320, 90);
int in    = Rnode_graph_add_input(graph, blend, "A", "number");

Rnode_graph_connect(graph, out, in);
Rnode_graph_set_node_content(graph, noise, Rwidget_create(R_WIDGET_SLIDER));  /* cualquier widget */
Rnode_graph_set_connect_callback(graph, may_link, NULL);                      /* rechaza bucles    */
Rnode_graph_set_flow_visible(graph, R_TRUE);                                  /* pulsos por los cables */

Editor de bloques

Bloques con forma, categorías y colores, ranuras para valores y cuerpos anidables. Ideal para lenguajes visuales, reglas o programación por bloques. Rblock_editor_save devuelve todos los scripts como texto y Rblock_editor_load los reconstruye.

Rid blocks = Rblock_editor_create();
Rblock_editor_add_kind(blocks, "print", "Escribir", R_BLOCK_SHAPE_STACK, "Salida");
int script = Rblock_editor_add_block(blocks, "print", 40, 40);
Rblock_editor_set_value(blocks, script, 0, "\"Hola\"");

const char* saved = Rblock_editor_save(blocks);
Rblock_editor_load(blocks, saved);

Efectos y shaders

raven_shader.h añade efectos de fragmento en SPIR-V y ocho efectos incorporados: aurora, shimmer, neon, ripple, plasma, grain, spotlight y mesh. Un Border puede usar un efecto como fondo, o un widget personalizado lo dibuja con Rdraw_shader.

Rid shader = Reffect_find("aurora");
RShaderLook look;
Rshader_look_defaults(shader, &look);
Rborder_set_effect(mi_border, shader, &look);

Widgets personalizados

Un widget R_WIDGET_CUSTOM se mide y se pinta con dos callbacks que usan las funciones Rdraw_... de raven_draw.h, y recibe sus eventos por Rwidget_set_event_callback. Rxml_register_tag le da un tag propio en XML con sus atributos, y Rwidget_set_destroy_callback avisa cuando desaparece para liberar lo que le pertenecía.

static void on_paint(Rid widget, RPainter* p, const RRect* rect, void* user) {
    float t = Rdraw_spring(p, &estado->escala, hovered ? 1.0f : 0.0f, R_MOTION_BOUNCY);
    Rdraw_rect(p, rect->x, rect->y, rect->w, rect->h, 12.0f * t, 0.13f, 0.83f, 0.93f, 1);
}

Rid custom = Rwidget_create(R_WIDGET_CUSTOM);
Rcustom_set_measure_callback(custom, on_measure, estado);
Rcustom_set_paint_callback(custom, on_paint, estado);
Rxml_register_tag("MiWidget", crear_mi_widget, poner_atributo, estado);

Accesibilidad

Cada widget es visto por el lector de pantalla del sistema con su rol, nombre, valor y estado, y se puede usar desde él: pulsar, alternar, poner un valor, editar texto y mover el foco. Funciona con UI Automation en Windows (Narrator, NVDA, JAWS), NSAccessibility en macOS (VoiceOver) y AT-SPI en Linux (Orca). No hay que añadir nada: los nombres salen de los textos y de la etiqueta que hay delante de un campo.

Raccessibility_follow_system();                  /* tamaño, contraste y movimiento del sistema */
Raccessibility_set_text_scale(1.5f);             /* todo el texto y los controles un 50 % más   */
Raccessibility_set_high_contrast(R_TRUE);        /* temas High Contrast Dark / Light            */
Raccessibility_set_color_filter(R_COLOR_FILTER_DEUTERANOPIA);
Rwidget_set_accessible_name(boton_cerrar, "Cerrar");
Raccessibility_announce("Archivo guardado", R_FALSE);
<Button Icon="close.png" AccessibleName="Cerrar" AccessibleDescription="Cierra el documento"/>

Los filtros de color corrigen (o, para diseñadores, simulan) protanopia, deuteranopia, tritanopia y acromatopsia. Raccessibility_set_reduce_motion detiene las animaciones; Raccessibility_set_focus_always_visible muestra siempre el anillo de foco y más grueso.

Idiomas y RTL

Las traducciones son tablas CSV: una columna por idioma, cualquier número de tablas, plurales con las reglas CLDR y recarga en vivo al guardar. Un texto que empieza por @ es una clave: el widget sigue el idioma cuando cambia.

key,en,fr,ar
menu.file,File,Fichier,ملف
greeting,"Hello, {0}!","Bonjour, {0} !",مرحبا {0}
files.one,{n} file,{n} fichier,ملف واحد
files.other,{n} files,{n} fichiers,{n} ملفات
Rlocale_load_csv("strings.csv");
Rlocale_set_language(Rlocale_get_system_language());

Rlabel_set_text(label, Rtr("menu.file"));
const char* args[] = { "Ada" };
Rlabel_set_text(hello, Rtr_format("greeting", args, 1));
Rlabel_set_text(count, Rtr_plural("files", 3));           /* "3 fichiers"              */
Rlabel_set_text(size, Rlocale_format_number(1234.5, 1));  /* "1 234,5"                 */
<Strings Source="strings.csv"/>
<Button Text="@menu.file" Tooltip="@menu.file.tip"/>

De derecha a izquierda

Un idioma escrito de derecha a izquierda (árabe, hebreo, persa, urdu…) refleja los layouts: cajas, grids, menús, barras de desplazamiento y alineaciones empiezan por la derecha. Rset_layout_direction(R_DIRECTION_RTL) lo fuerza para todas las ventanas; Rwidget_set_direction o Direction="RightToLeft" para una parte.

El texto con ambas direcciones se ordena con el algoritmo bidireccional de Unicode y las letras árabes toman sus formas unidas. Un carácter que la fuente incluida no tiene se dibuja con una fuente del sistema (Segoe UI, Noto, las fuentes CJK…), y los emoji a color se dibujan en color.

if (Rlocale_is_rtl()) {
    Rset_layout_direction(R_DIRECTION_RTL);
}

Rwidget_set_direction(panel, R_DIRECTION_RTL);
Rlocale_set_fallback_language("en");

Páginas web

raven_web es una librería opcional aparte que muestra páginas HTML, CSS y JavaScript dentro de una interfaz Raven. Raven no depende de ella; una aplicación que la quiere la enlaza junto a Raven (raven::web, opción RAVEN_BUILD_WEB).

#include <raven_web.h>

Rweb_register_xml();                              /* una vez tras Rinit: <WebView> es un tag */
Rid view = Rweb_view_create();                    /* o desde código                          */
Rweb_view_load_url(view, "https://example.org");
<WebView Name="docs" Url="https://example.org" Slot.Fill="1" OnChanged="docs.navigated"/>
<WebView Source="pages/help.html"/>
<WebView><![CDATA[<h1>Hola</h1><p>Desde <b>HTML</b>.</p>]]></WebView>

Cómo funciona

raven_web no contiene un navegador. Arranca uno que ya está instalado (cualquiera de la familia Chromium: Microsoft Edge, que viene con Windows 10 y 11, Google Chrome, Chromium, Brave, Vivaldi), oculto y en su propio proceso, y habla con él por una tubería con el protocolo DevTools:

  • el navegador manda una imagen de la página cada vez que cambia; la vista la muestra en una textura, como cualquier imagen de la interfaz (se puede recortar, desplazar, animar, poner bajo cristal o dentro de un nodo de un grafo);
  • la vista envía el ratón, las teclas y el texto que recibe;
  • los scripts se ejecutan en la página y la página manda mensajes de vuelta.
AspectoConsecuencia
El motorEl real, actualizado, sin nada que compilar ni distribuir: la librería son unas 3 000 líneas de C, 70 KB compilada.
Hace falta un navegadorRweb_is_available() lo dice. Sin uno, la vista muestra un mensaje y todo sigue siendo seguro de llamar.
Las páginas son imágenesLlegan un frame o dos después de lo que muestran; van bien para documentos y herramientas, no para un juego. Rweb_view_set_frames(view, R_WEB_FRAMES_JPEG, 80) las aligera para páginas que se mueven mucho (PNG, por defecto, mantiene el texto nítido).
Un navegador para todas las vistasArranca con la primera vista (una fracción de segundo) y se para al borrar la última.
Perfil propioCarpeta temporal, borrada al parar el navegador: sin cookies ni historial del usuario. Rweb_set_profile_folder da uno permanente.
LimitacionesEl cursor no cambia sobre enlaces; selectores de archivo, descargas, impresión, cámaras… necesitan una ventana del navegador. alert, confirm y prompt se aceptan al instante para que la página siga; un enlace que pide ventana nueva se abre en la vista.
PortapapelesCtrl+C, Ctrl+X y Ctrl+V llevan texto entre la página y el portapapeles del sistema.

El navegador se arranca con opciones que le impiden hablar con nada que no sean los sitios que muestra la aplicación: sin actualizaciones, sin informes, sin cuenta, sin servicios de mensajería y sin listas de navegación segura. Raven debe compilarse con su decodificador de imágenes (RAVEN_WITH_STB_IMAGE, activado por defecto): las imágenes de las páginas son PNG o JPEG.

Encontrar el navegador

En este orden: Rweb_set_browser_path(path); la variable de entorno RAVEN_WEB_BROWSER; después los sitios habituales (Program Files y los datos locales de la aplicación en Windows, empezando por Edge; el PATH en Linux: chromium, chromium-browser, google-chrome, microsoft-edge, brave-browser…; /Applications en macOS). Rweb_get_browser_path() dice cuál se encontró.

Rweb_set_browser_arguments("--proxy-server=localhost:8080") añade opciones a su línea de comandos (RAVEN_WEB_ARGUMENTS hace lo mismo). En Unix, a un navegador lanzado por el usuario root se le pasa --no-sandbox, porque si no se niega a arrancar; RAVEN_WEB_NO_SANDBOX lo hace para cualquiera (contenedores).

Es un widget como los demás: tamaño, slot, visibilidad, foco, tooltip… En XML acepta Url, Source (archivo relativo al documento), Html o el texto del elemento, Zoom y Frames/Quality (Png o Jpeg, 1..100).

JavaScript en ambos sentidos

static void on_result(Rid view, const char* result, const char* error, void* user) {
    /* result es JSON: "42", "\"texto\"", "{\"a\":1}", "null"; NULL si el script falló (ver error) */
}

Rweb_view_run_javascript(view, "document.title", on_result, NULL);
Rweb_view_run_javascript(view, "fetch('/api').then(r => r.json())", on_result, NULL);  /* las promesas se esperan */

static void on_message(Rid view, const char* message, void* user) { ... }
Rweb_view_set_message_callback(view, on_message, NULL);
window.raven.postMessage("guardado");            // un texto llega tal cual
window.raven.postMessage({ id: 3, ok: true });   // cualquier otra cosa, como JSON

Los comandos dados antes de que la vista esté lista (el navegador tarda un momento en arrancar) esperan y se envían en orden.

Para tags propios

raven_web no usa más que funciones públicas de Raven; tres existen para librerías como ella y sirven para cualquier widget hecho por código:

  • Rxml_register_tag(tag, create, set_attribute, user): da un tag a un widget construido por código, con atributos propios.
  • Rwidget_set_destroy_callback: avisa cuando el widget desaparece, para liberar lo que le pertenecía.
  • Rimage_decode: un archivo de imagen en memoria a píxeles RGBA, en cualquier hilo.
  • Rxml_resolve_path: la ruta de un archivo nombrado en el documento que se está cargando.

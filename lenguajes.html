Raven desde cualquier lenguaje

Raven es una librería C, así que cualquier lenguaje que pueda llamar a C puede usarla. El proyecto incluye bindings generados desde los headers para C++, Python, Rust, Go, C#, Zig y LuaJIT, además de un IDE y una forma de compilar la interfaz y el código en un solo archivo.

⚠

Antes de elegir el lenguaje: este paquete precompilado para Windows contiene lib/libraven.a, una librería estática para MinGW-w64 x64. C++ y Zig pueden enlazarla directamente. Python (ctypes), C# (P/Invoke) y LuaJIT (FFI) necesitan una DLL; Go y Rust pueden usar la estática, pero sus plantillas suelen esperar la compartida. Si vas a usar esos lenguajes, compila Raven desde el código fuente con -DRAVEN_BUILD_SHARED=ON o consigue un paquete compartido de la misma versión.

C++

El binding de C++ es un solo header, raven.hpp. Da una clase por tipo de handle (Window, Button, XmlNode…), acepta lambdas donde C pide un callback y añade un Painter para dibujar. Usa los headers de C y enlaza como un programa C, con la librería estática o compartida.

Compilar con CMake

Es la vía recomendada con este paquete. CMake ya conoce las librerías del sistema que necesita Raven en Windows.

cmake_minimum_required(VERSION 3.16)
project(mi_app CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_PREFIX_PATH "C:/ruta/a/raven-windows-mingw-x64-static")

find_package(raven REQUIRED)

add_executable(mi_app main.cpp)
target_include_directories(mi_app PRIVATE
    "${CMAKE_PREFIX_PATH}/share/raven/bindings/cpp")
target_link_libraries(mi_app PRIVATE raven::raven)
cmake -S . -B build -G "MinGW Makefiles"
cmake --build build
./build/mi_app.exe

Compilar a mano con MinGW

Si no usas CMake, además de libraven.a hay que enlazar las bibliotecas del sistema que usa la librería. Esta es la lista que necesita el paquete de Windows:

g++ -std=c++17 main.cpp ^
    -I"raven/include" -I"raven/share/raven/bindings/cpp" ^
    -L"raven/lib" -lraven ^
    -lwinhttp -lgdi32 -luser32 -lole32 -loleaut32 -luuid -lshell32 ^
    -lcomdlg32 -ldwmapi -lshcore -ladvapi32 -lcomctl32 -lws2_32 -lshlwapi ^
    -o mi_app.exe

El símbolo ^ continúa la línea en cmd.exe. En PowerShell, usa una sola línea o el acento grave (`) al final.

Una ventana en C++

#include <raven.hpp>

int main() {
    if (!raven::init(R_BACKEND_VULKAN)) {
        return 1;
    }

    auto window = raven::Window::create("Hola desde C++", 380, 220, R_WINDOW_DEFAULT);
    auto box    = raven::Panel(raven::Widget::create(R_WIDGET_VBOX));
    auto title  = raven::Label::create("Raven + C++");
    auto button = raven::Button::create("Salir");

    box.set_spacing(12.0f);
    box.slot_set_padding(20.0f, 20.0f, 20.0f, 20.0f);

    button.set_style(R_BUTTON_PRIMARY);
    button.set_clicked_callback([](Rid) { raven::quit(0); });

    box.add_child(title);
    box.add_child(button);
    window.set_content(box);

    while (raven::wait_frame(-1.0)) {}
    raven::shutdown();
    return 0;
}

Las lambdas con capturas se guardan y se liberan al reemplazar el callback, como en el ejemplo oficial del binding. Las acciones por nombre funcionan igual: raven::action_bind("quit", [](Rid, const char*) { raven::quit(0); });.

Python

El binding de Python es un módulo único, raven.py, basado en ctypes y sin dependencias. Los textos son str, los callbacks son funciones de Python y los valores que C devuelve por puntero se convierten en tuplas o resultados.

Instalar

# desde el registro, con la librería incluida
pip install raven-gui

# o con el binding del paquete y una raven.dll aparte
set RAVEN_LIBRARY=C:\ruta\a\raven.dll
python ejemplo.py

También puedes poner raven.dll junto a raven.py. Si usas el paquete estático de esta carpeta, antes necesitas compilar la variante compartida desde el código fuente.

Una ventana en Python

import raven as r

XML = """
<Window Title="Hola desde Python" Width="380" Height="220">
    <VBox Spacing="12" Slot.Padding="20">
        <Label Name="title" Text="Raven + Python" TextSize="20"/>
        <Button Text="Salir" Style="Primary" OnClicked="quit"/>
    </VBox>
</Window>
"""

if not r.Rinit(r.R_BACKEND_VULKAN):
    raise SystemExit("no se pudo iniciar Raven")

window = r.Rwindow_create_from_xml(XML)
r.Raction_bind("quit", lambda sender, action, user: r.Rquit(0))

while r.Rwait_frame(-1.0):
    pass

r.Rshutdown()

Para leer un campo: r.Rtext_input_get_text(r.Rwidget_find(window, "nombre")). Para cambiar una etiqueta: r.Rlabel_set_text(widget, "Hola"). Los errores de llamada llegan al callback de r.Rerror_set_callback con su código y su detalle.

Rust

El binding de Rust es un crate: raven::sys expone la API de C y el crate añade ayudas para &str, CString, acciones y textos. Se puede enlazar la librería compartida (por defecto) o la estática con RAVEN_STATIC=1.

Configurar

[dependencies]
raven = { package = "raven-gui", path = "../raven/share/raven/bindings/rust" }
# o, desde el registro:
# raven-gui = "0.1"
set RAVEN_LIB_DIR=C:\ruta\a\raven\lib
cargo run

# enlazar libraven.a en lugar de la DLL
set RAVEN_STATIC=1
cargo run

Una ventana en Rust

use raven::*;

const XML: &str = r#"
<Window Title="Hola desde Rust" Width="380" Height="220">
    <VBox Spacing="12" Slot.Padding="20">
        <Label Text="Raven + Rust" TextSize="20"/>
        <Button Text="Salir" Style="Primary" OnClicked="quit"/>
    </VBox>
</Window>"#;

fn main() {
    unsafe {
        if Rinit(R_BACKEND_VULKAN) == 0 {
            eprintln!("no se pudo iniciar Raven");
            return;
        }

        let _window = window_from_xml(XML);
        action_bind("quit", |_, _| Rquit(0));

        while Rwait_frame(-1.0) != 0 {}
        Rshutdown();
    }
}

El crate incluye text() y cstr() para convertir entre CStr y &str, y action_bind acepta closures. Para pasar textos a la API usa cstr("...").as_ptr().

Go, C#, Zig y LuaJIT

Los cuatro bindings se generan con el mismo script y cubren la misma API pública, con los nombres de C. La diferencia está en el sistema de tipos y en cómo se registran los callbacks.

LenguajeArchivoCómo se usa
Gogo/Paquete cgo. Exporta funciones con tipos Go y ActionBind, ErrorSetCallback, TimerStart para callbacks.
C#csharp/Raven.csP/Invoke: Raven.R.Rwindow_create(...), delegados y estructuras. Añade el archivo al proyecto y pon la DLL junto al ejecutable.
Zigzig/raven.zigDeclaraciones extern y extern struct. También puede leer el header con @cImport(@cInclude("Raven.h")).
LuaJITluajit/raven.luaDeclaraciones para el FFI de LuaJIT. local r = require("raven").

Go

Raven pertenece al hilo que la inicia: llama a runtime.LockOSThread() al principio de main. Las funciones que reciben punteros a estructuras, void* o callbacks de C no están envueltas; se llaman por cgo o se sustituyen por acciones.

package main

import (
    "runtime"
    "raven/raven"
)

const ui = `
<Window Title="Hola desde Go" Width="380" Height="220">
    <VBox Spacing="12" Slot.Padding="20">
        <Label Text="Raven + Go" TextSize="20"/>
        <Button Text="Salir" Style="Primary" OnClicked="quit"/>
    </VBox>
</Window>`

func main() {
    runtime.LockOSThread()

    if raven.Init(raven.R_BACKEND_VULKAN) == 0 {
        panic("no se pudo iniciar Raven")
    }

    _ = raven.WindowCreateFromXml(ui)
    raven.ActionBind("quit", func(sender raven.ID, action string) {
        raven.Quit(0)
    })

    for raven.WaitFrame(-1.0) != 0 {
    }
    raven.Shutdown()
}
set CGO_CFLAGS=-I"raven/include"
set CGO_LDFLAGS=-L"raven/lib"
go run .

Se puede instalar con dotnet add package Raven.Gui (incluye la librería) o copiar Raven.cs al proyecto y colocar raven.dll junto al ejecutable. También existe la integración de XMLC con Raven.XmlCs.targets.

Zig

const r = @import("raven.zig");

pub fn main() void {
    _ = r.Rinit(r.R_BACKEND_VULKAN);

    const xml =
        \\<Window Title="Hola desde Zig" Width="380" Height="220">
        \\  <VBox Spacing="12" Slot.Padding="20">
        \\    <Label Text="Raven + Zig" TextSize="20"/>
        \\    <Button Text="Salir" Style="Primary" OnClicked="quit"/>
        \\  </VBox>
        \\</Window>
    ;
    _ = r.Rwindow_create_from_xml(xml.ptr, xml.len);
    r.Raction_bind("quit", quit, null);

    while (r.Rwait_frame(-1.0) != 0) {}
    r.Rshutdown();
}

fn quit(_: r.Rid, _: ?[*:0]const u8, _: ?*anyopaque) callconv(.C) void {
    r.Rquit(0);
}
// build.zig
const exe = b.addExecutable(.{ .name = "mi_app", .root_source_file = b.path("src/main.zig") });
exe.linkSystemLibrary("raven");
exe.linkLibC();

XMLC en cada lenguaje

La interfaz en XML y el código que va con ella en bloques <script>, todo en un archivo. ravenc convierte el archivo entero en una fuente del lenguaje: los scripts se copian tal cual y el XML se transforma en tablas que construye Rwindow_create_from_compiled, sin leer XML en tiempo de ejecución.

En el XML, OnClicked="{on_save}" llama a la función on_save del script, y ui().status / ui.x es el widget con Name="status". El compilador del lenguaje comprueba las dos partes y los errores apuntan a la línea del archivo original.

ExtensiónLenguajeCompilado porFirma del callbackWidgets
.xmlcCCMake: raven_target_xmlcvoid f(Rid, const char*, void*)ui.x
.xmlc++, .xmlcppC++CMake: raven_target_xmlcvoid f(Rid, const char*) o lambdaui.x
.xmlrsRustCargo: raven_build::compilefn f(Rid, &str)ui().x
.xmlpyPythonimport raven_xmlpydef f(sender, action)ui.x
.xmlgoGo//go:generate ravencfunc f(raven.ID, string)ui.x
.xmlcsC#MSBuild: Raven.XmlCs.targetsstatic void F(uint, string)MainUi.x
.xmlzigZigxmlzig.compilefn f(Rid, ?[*:0]const u8, ?*anyopaque)ui.x
.xmlluaLuaJITrequire("raven_xmllua")function f(sender, action)ui.x
 
# C y C++: el archivo .xmlc es el propio ejecutable
find_package(raven REQUIRED)
add_executable(hello main.xmlc)
target_link_libraries(hello PRIVATE raven::raven)
raven_target_xmlc(hello)

En Rust, el archivo se procesa desde build.rs; en Go, go generate escribe un archivo //go:generate ravenc main.xmlgo -o main.xmlgo.go; en C# y Zig se integra en el .csproj / build.zig. Para desarrollo, los .xml normales se siguen leyendo en tiempo de ejecución y tienen recarga en vivo; los .xml* compilados son para distribuir.

<!-- src/main.xmlc: un programa C completo en un archivo -->
<script>
#include <Raven.h>
#include <stdio.h>

static int clicks = 0;

static void on_hello(Rid sender, const char* action, void* user) {
    char text[64];
    snprintf(text, sizeof text, "%d clics", ++clicks);
    Rlabel_set_text(ui.status, text);       /* Name="status" */
}

int main(void) {
    Rinit(R_BACKEND_VULKAN);
    Rid window = main_create();             /* generado por ravenc */
    Rwindow_show(window);
    while (Rwait_frame(-1.0)) {}
    Rshutdown();
    return 0;
}
</script>

<Window Title="Hola" Width="400" Height="200">
    <VBox Spacing="12" Slot.Padding="24">
        <Label Name="status" Text="Sin clics"/>
        <Button Text="Pulsar" Style="Primary" OnClicked="{on_hello}"/>
    </VBox>
</Window>

El IDE

raven_designer.exe es el IDE oficial, construido sobre la propia librería. Se abre con una carpeta de proyecto, un .xml o un archivo .xml*. En el paquete está en bin/.

raven_designer.exe
raven_designer.exe C:\proyectos\mi-editor
raven_designer.exe mi-interfaz.xml

Qué hace

◆ Proyectos en ocho lenguajes

Project > New project pide un nombre y un lenguaje (C, C++, Rust, Python, Go, C#, Zig, Lua) y escribe un proyecto que compila tal cual: la interfaz y su código en un main.xml*, los archivos de las herramientas del lenguaje y strings.csv.

◆ Editor visual

El mismo documento en cinco vistas sincronizadas: Widgets, Tree, Preview real, Properties y XML. Doble clic añade dentro de la selección; se puede mover, duplicar, envolver y desenvuelver.

◆ Código

Cada <script> se abre en una pestaña de su lenguaje junto a la vista previa. Los demás archivos se abren en un editor con autocompletado de la API de Raven, de los widgets (ui.<Name>) y de las claves de Rtr("...").

◆ Traducciones

Las tablas CSV como una rejilla: una fila por clave, una columna por idioma. Añadir, buscar, borrar; lo escrito aparece en la vista previa al instante.

◆ Build y run

Ctrl+B compila, F5 compila y ejecuta, Ctrl+F5 detiene. Usa CMake y el compilador para C/C++, Cargo para Rust, go generate/go build, dotnet, zig build, Python y LuaJIT.

◆ Errores en su línea

Los errores de GCC, Clang, MSVC, rustc, Go, CMake y ravenc van a Build y a las líneas de los editores, traducidos del archivo generado a la línea del .xml*. Doble clic abre el archivo en esa línea.

El editor visual usa solo la API pública. F7 abre la vista previa en una ventana propia, el menú View cambia el tema y una carpeta soltada en la ventana se abre como proyecto. Los ajustes de build se guardan en .raven-ide.

Preguntas frecuentes

¿Raven es gratis? ¿Qué licencia tiene?

Sí. Raven se distribuye bajo Apache License 2.0. Puedes usarlo en proyectos comerciales y privados; conserva el aviso de licencia y, si modificas archivos, indica los cambios. Las licencias de terceros (stb, Roboto, Roboto Mono, tweetnacl) están en share/raven/licenses/.

¿En qué estado está el proyecto?

En desarrollo activo. La API pública puede cambiar antes de la versión 1.0 y algunas áreas están incompletas: Wayland nativo, shaping OpenType completo para escrituras índicas, cursores múltiples y búsqueda en el editor, arrastrar de Raven a otra aplicación, knot/grupos/minimapa en el grafo, pistas anidadas y curvas en la línea de tiempo, imágenes remotas en Markdown. La documentación original mantiene una lista de “Not implemented yet”.

¿Qué necesito para compilar este paquete en Windows?

Un compilador de MinGW-w64 x64 y CMake. El paquete es estático y está hecho para ese compilador; no sirve para MSVC ni para MinGW de 32 bits. Con CMake, find_package(raven) y raven::raven ya añaden las librerías del sistema. Si compilas a mano, añade la lista de -lwinhttp -lgdi32 … de la sección de C++.

¿Por qué el enlace necesita tantas librerías de Windows?

Raven no enlaza Vulkan ni depende de Qt, GTK o Electron: trae su propio renderer, su decodificador de imágenes, sus fuentes y su asignador. Aun así, la capa de plataforma usa las APIs del sistema para ventanas, diálogos, DWM/blur, portapapeles, red, COM y criptografía. CMake las agrupa; el enlace manual las pide una a una.

¿Puedo usar Visual Studio?

Con este paquete no: las bibliotecas de MinGW y MSVC no son compatibles. Necesitas el paquete raven-windows-msvc-x64-* correspondiente, o compilar Raven desde el código fuente con Visual Studio. Lo mismo vale para Linux y macOS: usa el paquete de tu plataforma o compila desde fuente.

¿Cómo distribuyo mi aplicación?

Con la variante estática, el ejecutable enlaza libraven.a y no necesita una DLL de Raven; aun así, distribuye las licencias de terceros. Con la compartida, lleva raven.dll junto al ejecutable (y las DLLs de MinGW que falten: libgcc_s_seh-1.dll, libstdc++-6.dll, libwinpthread-1.dll si no son estáticas). Las fuentes e imágenes que cargues por ruta también deben viajar con la aplicación.

¿Necesito Vulkan instalado?

Para ejecutar una aplicación ya compilada, no: Raven crea su instancia y su dispositivo Vulkan, y en Windows usa el runtime del sistema/driver. Para compilar desde el código fuente sí necesitas los headers de Vulkan; no forman parte del repositorio. En macOS se usa MoltenVK. También existe el backend nulo (R_BACKEND_NULL) para tests sin ventana ni GPU.

¿Puedo usar OpenGL o Direct3D en vez de Vulkan?

El renderer de Raven es Vulkan, pero un Viewport puede mostrar una textura de otra API, dibujar en el render pass o crear una ventana hija nativa donde tu motor use OpenGL o Direct3D. Para sustituir el renderer completo existe RBackendVTable y Rbackend_register; el backend nulo es la plantilla.

¿El editor de texto tiene language server?

No. El editor colorea, cierra pares, indenta, comenta y propone palabras a partir del texto y del lenguaje, pero no entiende un programa entero. Para eso hay dos puntos de extensión: Rtext_editor_set_completion_callback y Rtext_editor_add_marker. Un cliente LSP se conectaría ahí; Raven no incluye uno.

¿Por qué la vista web no carga?

raven_web no incluye un navegador: conduce uno de la familia Chromium que ya esté instalado. Comprueba Rweb_is_available() y Rweb_get_browser_path(). Si no encuentra Edge o Chrome, define RAVEN_WEB_BROWSER o llama a Rweb_set_browser_path. Para diagnóstico, RAVEN_WEB_TRACE=1 imprime cada mensaje y RAVEN_WEB_DEBUG=1 deja pasar la salida de error del navegador.

¿Hay binarios para Linux o macOS?

El proyecto publica paquetes por plataforma y compilador. Esta carpeta es solo Windows MinGW-w64 x64 estático. Para Linux o macOS, compila desde el código fuente con CMake; en macOS se usa MoltenVK y en Linux X11 (Wayland funciona a través de XWayland).

💡

Si algo no arranca, empieza por Problemas frecuentes de la guía: cubre el backend, la DLL que falta, el compilador equivocado, la fuente que no se encuentra y el bucle que no dibuja.

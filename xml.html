Referencia XML

Una interfaz, escrita una vez

Reglas y tipos de valor

Un documento XML se carga con Rwindow_create_from_xml_file (raíz <Window>) o con Rwidget_create_from_xml (cualquier widget como raíz). Los tags son tipos de widget; los atributos, propiedades; los Slot.* son el slot del hijo.

Rid window = Rwindow_create_from_xml_file("editor.xml");
Rid panel  = Rwidget_create_from_xml(texto, strlen(texto));
  • Los nombres de tag y atributo no distinguen mayúsculas.
  • El parser entiende elementos, atributos, texto, comentarios, CDATA, las cinco entidades predefinidas y referencias numéricas. Los archivos son UTF-8; no hay DTD ni namespaces.
  • Dentro de un valor de atributo, < y & se escriben &lt; y &amp;: If="{Count &lt; 3}".
  • El texto dentro de un elemento es su atributo Text: <Label>Hola</Label> equivale a <Label Text="Hola"/>.
  • Los hijos se crean primero y después se aplican los atributos del padre, para que Selected="1" o ActiveTab="2" puedan referirse a ellos.
  • Un tag o atributo desconocido, o un valor inválido, genera un warning con línea y columna a través del callback de errores; la carga continúa.
  • Las rutas (Source, Font) son relativas al archivo XML, o a Rxml_set_base_path si el documento viene de memoria. Un archivo se carga una vez y se comparte.

BlockEditor

Un editor de bloques que encajan entre sí, al estilo Scratch. Se declaran los tipos con <Kind> y las categorías con <Category>:

<BlockEditor Height="340">
    <Category Name="Eventos" Color="#FFBF00"/>
    <Category Name="Control" Color="#FFAB19"/>

    <Kind Name="inicio" Label="when started" Shape="Hat" Category="Eventos"/>
    <Kind Name="repetir" Label="repeat %n{10}" Shape="C" Category="Control"/>
    <Kind Name="mover" Label="move %n{10} steps" Shape="Statement" Category="Control"/>
    <Kind Name="suma" Label="%n + %n" Shape="Reporter" Category="Control"/>
</BlockEditor>

En Label, %n es un número, %s un texto, %b una condición, %r cualquier valor y %m un menú. {10} después de un slot es su valor por defecto. | separa las secciones de un bloque C (cada una seguida de una boca): "if %b then|else".

Markdown

Markdown="true" en un Label renderiza el texto: encabezados, negrita, cursiva, tachado, código, enlaces, listas (con casillas), citas, bloques de código coloreados, tablas, reglas, saltos de línea e imágenes. En un TextEditor, el mismo flag mantiene el texto tal como se escribe y lo estiliza donde está.

<Label Markdown="true" Wrap="true">
## Notas
Texto **fuerte**, *énfasis*, `código` y un [enlace](https://example.org).

- una lista
- [x] con casilla

> una cita

| Columna | Valor |
|---|---|
| una | 1 |
</Label>

Un enlace [texto](https://...) abre el navegador del sistema; [texto](action:nombre) dispara la acción nombre. Rlabel_set_link_callback los recibe todos. Las imágenes remotas se cargan de forma asíncrona (requiere curl en macOS/Linux y WinHTTP en Windows).

Tags propios

Un documento puede declarar sus propios tags con parámetros y reutilizarlos como cualquier widget de la librería:

<Widget Name="Field" Label="Name" Hint="" Wide="false">
    <HBox Spacing="8">
        <Label Text="{Label}:" Width="{Wide ? 140 : 90}"/>
        <TextInput Placeholder="{Hint}" Slot.Fill="1"/>
        <Children/>
    </HBox>
</Widget>

<Field Label="Email" Hint="tu@ejemplo.com" Name="email"/>
<Field Label="Contraseña" Wide="true"><Button Text="Mostrar"/></Field>
  • Los atributos de <Widget> distintos de Name son sus parámetros, con su valor por defecto. Contiene exactamente un elemento: lo que representa el tag.
  • Dentro, {...} se calcula y se sustituye. {{ y }} escriben una llave literal.
  • Donde se usa el tag, los atributos que son parámetros pasan sus valores; los demás (Name, Slot.Fill, OnClicked, Material...) van al elemento que representa el tag. El texto dentro del tag es su Text.
  • <Children/> se sustituye por los hijos dados al tag; <Children Name="footer"/> por los marcados con Into="footer".
  • Una declaración se conoce desde que se lee hasta que la librería se cierra, en todos los documentos posteriores. Re-declarar un nombre lo reemplaza. No puede tomar el nombre de un tag de la librería.
  • Un tag puede usar tags declarados antes, pero no a sí mismo.

Expresiones

Números, textos entre comillas simples, parámetros y variables; + - * / % (+ concatena textos), == != < <= > >=, && || !, a ? b : c, paréntesis; min(a,b), max(a,b), round, floor, ceil, abs, len(texto), upper, lower, empty(texto), default(valor, alternativo). {Instance} es un número distinto para cada uso de un tag, útil para nombres únicos. Es falso false, 0 y el texto vacío.

💡

Las llaves solo se evalúan dentro de un <Widget>, un <Repeat> o un <ForEach>. En el resto del documento son caracteres normales, así que no rompen CSS ni plantillas.

XMLC: un archivo, cualquier lenguaje

XMLC es la forma de escribir la interfaz y su código en un solo archivo. Los scripts son código normal dentro de <script>; el XML se convierte en tablas que construye Rwindow_create_from_compiled, sin leer XML en tiempo de ejecución. ravenc genera un fuente del lenguaje elegido, y el compilador de ese lenguaje comprueba todo.

<!-- src/main.xmlrs: un programa Rust completo -->
<script>
use raven::*;
use std::sync::atomic::{AtomicI32, Ordering};

static CLICKS: AtomicI32 = AtomicI32::new(0);

fn on_hello(_sender: Rid, _action: &str) {           // OnClicked="{on_hello}"
    let n = CLICKS.fetch_add(1, Ordering::SeqCst) + 1;
    let text = cstr(&format!("{} clicks", n));
    unsafe { Rlabel_set_text(ui().status, text.as_ptr()) };   // Name="status"
}

fn main() {
    unsafe { Rinit(R_BACKEND_VULKAN) };
    main_create();                                     // hecho por ravenc
    unsafe { while Rdraw_frame() != 0 {} Rshutdown() };
}
</script>

<Window Title="Hello" Width="400" Height="200">
    <VBox Spacing="12" Slot.Padding="24">
        <Label Name="status">Not clicked yet</Label>
        <Button Text="Click me" Style="Primary" OnClicked="{on_hello}"/>
    </VBox>
</Window>

El compilador

ravenc main.xmlrs -o main.xmlrs.rs
ravenc main.xmlpy -o main.xmlpy.py --lang python --name main

ravenc deduce el lenguaje de la extensión. --lang lo fuerza (c, cpp, rust, python, go, csharp, zig, lua) y --name cambia el nombre de la función generada (NAME_create; por defecto, el nombre del archivo).

Integración por lenguaje

# C y C++: CMake
find_package(raven REQUIRED)
add_executable(hello main.xmlc)          # o main.xmlc++
target_link_libraries(hello PRIVATE raven::raven)
raven_target_xmlc(hello)                 # ravenc procesa cada .xmlc / .xmlc++ del target
// build.rs: convierte src/main.xmlrs en $OUT_DIR/main.xmlrs.rs
fn main() { raven_build::compile("src/main.xmlrs"); }

// src/main.rs: el programa es el .xmlrs
include!(concat!(env!("OUT_DIR"), "/main.xmlrs.rs"));
import raven_xmlpy
import main          # main.xmlpy, compilado al importarlo

# o desde la línea de comandos:
# python -m raven_xmlpy main.xmlpy
//go:generate ravenc main.xmlgo -o main.xmlgo.go
package main

// El archivo generado declara main_create(), ui y los callbacks.

En C# se importa bindings/csharp/Raven.XmlCs.targets desde el .csproj; en Zig, xmlzig.compile desde build.zig; en LuaJIT, require("raven_xmllua") antes de importar el módulo compilado.

Ventajas de XMLC

  • Los scripts son código normal: cualquier header, crate, paquete o módulo; sin escapes XML (a < b && c se escribe tal cual). Tantos <script> como quieras.
  • Los errores apuntan a tu archivo. En Rust, Go, C# y Zig los scripts conservan sus números de línea en el archivo generado; en C y C++ se usa #line. El compilador dice main.xmlrs:12 y el IDE lo abre ahí.
  • No hay header ni glue: en C, otro archivo solo declara Rid main_create(void);.
  • Todo lo del XML funciona igual compilado: tags declarados, @claves de traducciones, temas, Slot.*...
  • Los .xml planos se siguen leyendo en tiempo de ejecución con recarga en vivo: úsalos mientras diseñas y compila a .xml… para distribuir.

Recarga en vivo

Una ventana o widget creado desde archivo, los archivos que incluye, los archivos de tags declarados y los archivos de tema se vigilan mientras la aplicación corre. Al guardar, la interfaz sigue estos criterios:

  • Un elemento cuyos atributos cambiaron conserva su widget (handle, callbacks, estado: scroll, texto escrito, selección) y recibe los nuevos valores.
  • Los elementos se emparejan por Name; si no hay, por contenido; si tampoco, por posición entre los del mismo tag. Los nuevos se crean; los que desaparecen se borran.
  • Un widget que gestiona su propio contenido (ComboBox, Timeline, NodeGraph, menús...) se reconstruye cuando cambian los elementos internos.
  • Un archivo con un error no cambia nada y reporta el error.
Rxml_set_reload_callback(on_reload, NULL);   /* tras cada recarga: vuelve a buscar widgets */
Rxml_set_live_reload(R_FALSE);               /* desactiva la vigilancia (o RAVEN_LIVE_RELOAD=0) */
Rxml_check_files();                          /* comprueba ahora en vez de al siguiente tick */

Los documentos creados desde texto (Rwindow_create_from_xml) no son archivos y no se vigilan. La vigilancia comprueba cinco veces por segundo.

Documentos y herramientas

Para un editor visual o una herramienta que manipule la interfaz, Raven expone el XML como un árbol de nodos editable:

RXmlError error;
Rid doc = Rxml_document_parse(xml, strlen(xml), &error);
if (doc == R_INVALID_ID) {
    printf("línea %d: %s\n", error.line, error.message);
}

Rid root = Rxml_document_get_root(doc);
Rid child = Rxml_node_add_child(root, "Label", -1);
Rxml_node_set_attribute(child, "Text", "Hola & adiós");

const char* text = Rxml_document_to_string(doc);   /* comentarios conservados */
Rxml_document_save(doc, "salida.xml");

Rid widget = Rxml_document_create_widget(doc);
Rid nodo = Rwidget_get_xml_node(widget);           /* el widget conoce su nodo */
Rid w = Rxml_node_get_widget(nodo);                /* y el nodo su widget */
Rxml_document_destroy(doc);

La API de introspección Rxml_get_tag_count, Rxml_get_tag_name, Rxml_get_tag_description, Rxml_get_tag_children, Rxml_get_attribute_count y Rxml_get_attribute_info devuelve las tablas de esta página como datos. El diseñador raven_designer está construido sobre ellas.

💡

Rwidget_set_attribute(widget, "Text", "Hola") cambia una propiedad en tiempo de ejecución con el mismo nombre que usarías en XML. Es la forma rápida de ajustar algo sin buscar la función específica.

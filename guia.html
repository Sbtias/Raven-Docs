Instalación

Raven se distribuye como un paquete CMake. En Windows conviven cuatro variantes: Visual C++ y MinGW-w64, cada una estática y compartida. Las bibliotecas de un compilador no sirven para el otro. Este paquete es MinGW-w64 x64, estático.

Qué hay dentro del paquete

RutaQué es
include/Raven.hLa API pública completa en un solo include.
include/raven/Un header por área: core, window, widget, layout, controls, tools, xml...
lib/libraven.aLa librería estática para MinGW-w64 x64.
lib/cmake/raven/El paquete CMake: find_package(raven) y raven::raven.
bin/ravenc.exeEl compilador de XMLC: convierte un .xmlc, .xmlrs, .xmlpy... en código del lenguaje.
bin/raven_designer.exeEl IDE oficial: proyectos, editor visual, XML, traducciones, build y run.
share/raven/README, documentación, bindings y licencias de terceros.
⚠

Usa MinGW-w64, no Visual C++, para este paquete concreto. Si compilas con MSVC necesitas la variante msvc-static o msvc-shared. La DLL compartida, en cambio, puede cargarla cualquier lenguaje.

Requisitos

  • Windows 10 u 11 de 64 bits.
  • Un compilador de MinGW-w64 (GCC) y CMake 3.16 o posterior. Ninja es opcional pero recomendable.
  • Un driver Vulkan instalado (viene con los drivers de GPU de NVIDIA, AMD e Intel). El header de Vulkan solo hace falta para compilar Raven desde el código fuente, no para usar este paquete.

Con CMake (recomendado)

Crea un CMakeLists.txt que apunte a la carpeta del paquete con CMAKE_PREFIX_PATH:

cmake_minimum_required(VERSION 3.16)
project(mi_app C)

set(CMAKE_PREFIX_PATH "C:/Users/tu_usuario/Downloads/raven-windows-mingw-x64-static")
find_package(raven REQUIRED)

add_executable(mi_app main.c)
target_link_libraries(mi_app PRIVATE raven::raven)

Configura con el generador de MinGW y compila:

cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
./build/mi_app.exe

Si CMake no encuentra el paquete, pásale la ruta en la línea de comandos en vez de dentro del archivo:

cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_PREFIX_PATH="C:/ruta/a/raven-windows-mingw-x64-static"

Con gcc a mano

La librería estática necesita además las bibliotecas del sistema de Windows. Esta línea funciona con el paquete y un GCC de MinGW-w64:

gcc main.c -I"raven/include" -L"raven/lib" -lraven \
  -lwinhttp -lgdi32 -luser32 -lole32 -loleaut32 -luuid -lshell32 \
  -lcomdlg32 -ldwmapi -lshcore -ladvapi32 -lcomctl32 -lws2_32 -lshlwapi \
  -o mi_app.exe

Añade -mwindows si no quieres la consola detrás de la ventana. Para depurar, compila con -g y sin -mwindows.

Compilar Raven desde el código fuente

Si en lugar de usar el paquete quieres construir la librería, necesitas CMake, un compilador C11 y los headers de Vulkan (se descargan solos si no hay SDK). En MSYS2 MINGW64:

pacman -S --needed git mingw-w64-x86_64-gcc mingw-w64-x86_64-cmake mingw-w64-x86_64-ninja
git clone https://github.com/oscar-soirey/Raven.git
cd Raven
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
cmake --install build --prefix install

En Visual Studio 2022, abre Developer PowerShell for VS 2022 y ejecuta cmake -S . -B build, cmake --build build --config Release --parallel y cmake --install build --config Release --prefix install. Los programas quedan en build\bin\Release.

Tu primera ventana

El programa mínimo: iniciar, crear una ventana, darle contenido y esperar frames hasta que el usuario cierre.

#include <Raven.h>

static void on_quit(Rid sender, const char* action, void* user) {
    (void)sender; (void)action; (void)user;
    Rquit(0);
}

int main(void) {
    if (!Rinit(R_BACKEND_VULKAN)) return 1;

    Rid window = Rwindow_create("Mi primera app", 640, 400, R_WINDOW_DEFAULT);
    Rid root = Rwidget_create(R_WIDGET_VBOX);
    Rpanel_set_spacing(root, 10);
    Rslot_set_padding(root, 20, 20, 20, 20);

    Rid title = Rwidget_add_child(root, Rlabel_create("Hola, Raven"));
    Rlabel_set_text_size(title, 22);

    Rid input = Rwidget_add_child(root, Rtext_input_create());
    Rtext_input_set_placeholder(input, "Escribe algo...");

    Rid button = Rwidget_add_child(root, Rbutton_create("Salir"));
    Rbutton_set_style(button, R_BUTTON_PRIMARY);
    Rbutton_set_clicked_callback(button, on_quit, NULL);
    Rslot_set_halign(button, R_HALIGN_LEFT);

    Rwindow_set_content(window, root);
    while (Rwait_frame(-1.0)) {}
    Rshutdown();
    return 0;
}

💡

El XML solo construye el árbol. Después, todo son handles normales: puedes buscar widgets con Rwidget_find, cambiarles propiedades o añadir hijos desde C en cualquier momento.

El bucle de frames

Raven no tiene bucle propio. Tú decides cuándo se produce un frame:

/* Un juego o un motor: nunca espera, un frame por vuelta. */
while (Rdraw_frame()) {
    actualizar_mi_escena();
    renderizar_mi_escena();
}

/* Una herramienta: duerme hasta que pase algo. */
while (Rwait_frame(-1.0)) {
}

return Rget_exit_code();
  • Rdraw_frame() procesa eventos pendientes, timers y tareas, y luego mide, pinta y presenta solo las ventanas que cambiaron.
  • Rwait_frame(segundos) hace lo mismo pero antes duerme hasta que haya un evento, un timer, una tarea o una animación en movimiento. Un valor negativo espera sin límite; 0 no duerme.
  • Ambos devuelven R_FALSE después de Rquit() o cuando se cierra la última ventana.
  • Una ventana sin cambios no se vuelve a dibujar: el coste en reposo es prácticamente cero.

Si haces una operación larga y quieres que la interfaz siga respondiendo, llama a Rpoll_events() de vez en cuando, o mejor reparte el trabajo con Rtask_run_async / Rparallel_for.

Handles, errores y nombres

Todo es un Rid

Ventanas, widgets, fuentes, texturas, timers, documentos XML y nodos son handles opacos de 32 bits. Llevan un contador de generación, así que usar un objeto borrado se detecta y se reporta en vez de provocar un acceso inválido. R_INVALID_ID y 0 nunca son handles válidos.

Borrar un widget borra a sus hijos; borrar una ventana borra su contenido. Aun así, el patrón recomendado es dejar que el padre borre a sus hijos.

Convención de nombres

FormaEjemplo
R<objeto>_<acción>Rwindow_create, Rbutton_set_text, Rslot_set_fill
R<acción>Rinit, Rdraw_frame, Rquit, Rshutdown
R<Nombre>Rid, REvent, RInitDesc, RPainter
R_<NOMBRE>R_WIDGET_VBOX, R_KEY_ESCAPE, R_THEME_GLASS_DARK
RAVEN_<NOMBRE>Macros y opciones de compilación (RAVEN_VERSION_MAJOR)

Los nombres que empiezan por rvn_ o RVN_ son internos y no se exportan.

Errores

static void on_error(RError code, RSeverity severity, const char* detail) {
    fprintf(stderr, "[Raven] %s: %s\n", Rerror_to_string(code), detail);
}

Rerror_set_callback(on_error);        /* antes o después de Rinit */

/* O consulta el último error y límpialo: */
const char* detail = NULL;
RSeverity severity;
RError error = Rerror_get_last(&detail, &severity);
if (error != R_NO_ERROR) {
    printf("%s: %s\n", Rerror_to_string(error), detail);
}

La macro Rerror_check() imprime el último error con archivo y línea. Los errores del renderer llegan desde el hilo de render, así que el callback debe ser seguro para llamarse desde varios hilos.

Inicio con opciones

RInitDesc desc = {0};
desc.backend = R_BACKEND_VULKAN;   /* o R_BACKEND_NULL para tests */

Rinit_ex(&desc);

Layout y slots

El layout es el de Slate, en dos pasadas: cada widget calcula el tamaño que le gustaría, de abajo arriba; después cada panel reparte rectángulos, de arriba abajo. La colocación de un hijo se guarda en el hijo, en su slot, y la lee su padre.

Rid fila = Rwidget_add_child(parent, Rwidget_create(R_WIDGET_HBOX));
Rpanel_set_spacing(fila, 8);

Rid nombre = Rwidget_add_child(fila, Rwidget_create(R_WIDGET_TEXT_INPUT));
Rslot_set_fill(nombre, 1.0f);              /* ocupa el ancho libre */
Rslot_set_padding(nombre, 0, 0, 8, 0);

Rid ok = Rwidget_add_child(fila, Rbutton_create("OK"));
Rslot_set_valign(ok, R_VALIGN_CENTER);     /* su altura, centrado */
Rslot_set_padding(ok, 8, 0, 0, 0);

Los tamaños son unidades lógicas: se multiplican por la escala del monitor. Solo se vuelve a medir y colocar la parte del árbol que cambió.

💡

Si un hijo no aparece, revisa dos cosas: que su padre sea un panel con layout (VBox, HBox, Grid...) y que el slot no lo esté dejando con tamaño cero. Para depurar, Rwidget_get_rect() y Rwidget_get_desired_size() te dicen el rectángulo real y el deseado.

La HeaderBar dibuja el título y los botones de la ventana, y puede contener cualquier widget. Arrastrarla mueve la ventana, doble clic la maximiza y los bordes siguen redimensionando. Eventos y acciones

Raven tiene dos formas de conectar la interfaz con tu código: acciones por nombre (cómodas desde XML y scripts) y callbacks directos (cómodos desde C).

Acciones

static void on_save(Rid sender, const char* action, void* user) {
    printf("guardar desde %s\n", action);
}

Raction_bind("file.save", on_save, NULL);
Raction_fire("file.save", R_INVALID_ID);       /* dispara como un widget */

/* Recibe toda acción sin binding, por ejemplo un puente de scripts. */
Raction_set_default_handler(on_any_action, NULL);

En XML, OnClicked, OnChanged, OnCommitted y OnActivated son sinónimos del action principal del widget. Se resuelven al disparar, así que puedes enlazarlas antes o después de crear la interfaz.

Callbacks

Rbutton_set_clicked_callback(button, on_click, user);
Rtext_input_set_changed_callback(input, on_text, user);
Rlist_view_set_selection_changed_callback(list, on_selection, user);
Rwidget_set_event_callback(widget, on_raw_event, user);   /* ratón, teclado, foco... */
Rwindow_set_resize_callback(window, on_resize, user);
Rwindow_set_close_callback(window, on_close, user);

Atajos de teclado

Rwindow_register_shortcut(window, R_KEY_S, R_MOD_CTRL, "file.save");
Rwindow_unregister_shortcut(window, R_KEY_S, R_MOD_CTRL);

Drag and drop de entrada

static int on_drop(Rid target, const RDropEvent* event, void* user) {
    if (event->phase == R_DROP_DROPPED && event->path_count > 0) {
        abrir_archivo(event->paths[0]);
    }
    return R_TRUE;   /* "lo acepto": el objetivo se resalta mientras el cursor encima */
}

Rwindow_set_drop_callback(window, on_drop, NULL);
Rwidget_set_drop_callback(panel, on_drop, NULL);

Se reciben archivos y texto arrastrados desde otras aplicaciones. Arrastrar desde una ventana de Raven hacia otra aplicación todavía no está implementado, aunque sí existe Rdrag_begin para arrastres internos (por ejemplo, pestañas o tiles).

Memoria e hilos

El asignador

Raven no llama a malloc. Toma memoria del sistema en regiones de 4 MB y la reparte con su propio heap TLSF: asignación y liberación en tiempo constante, vecinos libres fusionados. Las fuentes y decodificadores incluidos también lo usan.

RAllocator mio = { mi_alloc, mi_realloc, mi_free, mi_datos };
Rset_allocator(&mio);          /* antes de Rinit */

RMemoryStats stats;
Rmemory_get_stats(&stats);
printf("en uso: %zu, pico: %zu, bloques: %zu\n",
       stats.used_bytes, stats.peak_bytes, stats.allocation_count);

Rmemory_check();               /* verifica la estructura del heap */
Rmemory_trim();                /* devuelve al SO las regiones vacías */

Para que Valgrind o un profiler de heap vean los bloques, usa Rset_allocator(Rallocator_get_system()) o define RAVEN_ALLOCATOR=system. También es el modo por defecto en builds con AddressSanitizer.

Hilos

  • El hilo que llama a Rinit es el hilo de interfaz. Todas las funciones se llaman desde ahí salvo las documentadas como thread-safe.
  • Desde otro hilo, cambia la UI con Rtask_post(función, datos): se ejecuta en el hilo de UI en el siguiente frame.
  • Rtask_run_async y Rparallel_for reparten trabajo entre los hilos del job system.
  • Rtexture_create_from_file_async decodifica en segundo plano; los widgets que usan la textura se actualizan cuando está lista.
  • Los callbacks de dibujo de un Viewport corren en el hilo de render.
  • Son thread-safe: Rtask_post, Rtask_run_async, Rwake_up, Rquit, Rwindow_request_redraw, Rget_time y Rmemory_*.
static void aplicar_resultado(void* data) {
    Resultado* r = (Resultado*)data;
    Rlabel_set_text(label, r->texto);      /* ya estamos en el hilo de UI */
    free(r);
}

/* desde un hilo de trabajo */
Rtask_post(aplicar_resultado, resultado);

Animaciones

Los controles se mueven solos con springs: los botones se aplastan al pulsarlos y rebotan, los switches se deslizan, los popups salen de lo que los abrió y las listas se estiran en los extremos. Tú solo decides las transiciones y los ajustes globales.

Rwidget_set_transition(card, R_TRANSITION_FLY_UP, 0.1f);  /* cada vez que aparece */
Rwidget_play_transition(card, R_TRANSITION_DROP, 0.0f);   /* una vez, ahora */

Rset_animation_speed(0.25f);          /* cámara lenta */
Rset_animations_enabled(R_FALSE);     /* "reduce motion" */
Rset_animation_time_step(1.0 / 60);   /* frames deterministas, para vídeo o tests */
TransicionesMotion de los springs
Fade, Pop, Zoom, FlyUp, FlyDown, FlyLeft, FlyRight, Drop, SlideLeft, SlideRightR_MOTION_SNAPPY, R_MOTION_SMOOTH, R_MOTION_BOUNCY, R_MOTION_WOBBLY

En un widget personalizado, dentro del callback de pintado, puedes animar un valor con Rdraw_spring(painter, &estado, objetivo, R_MOTION_BOUNCY). Mientras algo se mueve, la ventana sigue pidiendo frames; cuando todo está quieto, Rwait_frame vuelve a dormir.

Viewports

Un Viewport es el puente entre Raven y tu propio contenido renderizado. Hay tres modos:

/* 1. Textura: cualquier imagen, mostrada como un widget (recortada, UI encima). */
Rviewport_set_texture(viewport, texture);
/*    Vulkan sin copia:  Rvulkan_texture_create_from_image_view(view, 0, w, h)
      OpenGL sin copia:  Rvulkan_texture_create_shared + GL_EXT_memory_object
      Cualquier API:      Rtexture_update(texture, rgba, w, h)                  */

/* 2. Callback de dibujo: tus llamadas Vulkan dentro del render pass de Raven. */
Rviewport_set_draw_callback(viewport, on_draw, user);

/* 3. Ventana hija nativa: un HWND / X11 Window para OpenGL, Direct3D, etc. */
Rviewport_set_native(viewport, R_TRUE);
RNativeWindow native;
Rviewport_get_native_handle(viewport, &native);

Para renderizar la UI con el dispositivo de un motor en vez de uno creado por Raven, llama a Rvulkan_set_external_device() y Rvulkan_set_queue_lock_callbacks() antes de Rinit. Está documentado en raven_vulkan.h.

Rendimiento

El benchmark incluido (raven_benchmark, compilado con los tests) mide un árbol grande sin GPU. En la máquina de 2 núcleos usada para el desarrollo, build release:

12 000 widgets, 27 800 primitivasTiempo
Primer layout2 a 3 ms
Repintado completo1,3 a 2,3 ms, una draw call
Layout tras cambiar una etiqueta0,03 a 0,05 ms

Mide en tu máquina con raven_benchmark 160 0 y raven_benchmark 160 -1. Para ver el coste real por frame, lee RFrameStats:

RFrameStats stats;
Rwindow_get_frame_stats(window, &stats);
printf("layout %.2f ms, paint %.2f ms, render %.2f ms, %u widgets, %u draw calls\n",
       stats.layout_ms, stats.paint_ms, stats.render_ms,
       stats.widget_count, stats.draw_call_count);

El glass tiene un coste mayor: un frame con cristal se dibuja primero en una imagen offscreen y se copia/difumina donde empieza el cristal. Un frame sin glass va directo a la ventana. stats.backdrop_count te dice cuántas veces se copió y difuminó en el último frame.

Problemas frecuentes

SíntomaCausa probable y solución
La ventana no aparece o se cierra solaNo hay driver Vulkan, o el backend falló. Registra Rerror_set_callback y comprueba que Rinit devolvió R_TRUE. Prueba R_BACKEND_NULL para aislar.
undefined reference to ... al enlazarFaltan bibliotecas del sistema de Windows. Usa el comando de gcc de esta guía o enlaza con CMake.
raven.dll no se encuentraEste paquete es estático. Si usas una variante compartida, copia la DLL junto al .exe o añade su carpeta al PATH.
CMake no encuentra ravenPasa -DCMAKE_PREFIX_PATH=... apuntando a la carpeta que contiene lib/cmake/raven.
Errores raros de ABI o crashes al enlazarEstás mezclando MSVC con MinGW. Usa la variante del paquete correspondiente a tu compilador.
El XML no se recarga al guardarComprueba Rxml_get_live_reload() y que no esté definido RAVEN_LIVE_RELOAD=0. Los documentos creados desde texto no se vigilan, solo los archivos.
Texto invisible o glifos rarosLa fuente incluida cubre Latin-1 y Latin Extended-A. Para otros scripts, Raven pide una fuente del sistema; si falta, configura una con Rfont_set_fallback.
El web view no muestra nadaRweb_is_available() devuelve si hay un navegador Chromium instalado. Sin navegador, el widget muestra un aviso. Prueba RAVEN_WEB_TRACE=1.
